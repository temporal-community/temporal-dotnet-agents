# Known-pending factory-first `AddTool` defect sites, as `<doc-path> <count>`.
#
# WHAT THESE ARE
#   `AddTool` has two overloads: AddTool(AIFunction tool, ...) and
#   AddTool(string name, Func<IServiceProvider, AIFunction> factory, ...). The factory overload
#   takes the NAME FIRST. Passing the factory lambda as the first argument —
#   `AddTool(sp => AIFunctionFactory.Create(...))` — binds to neither and does not compile.
#
# WHY A COUNT RATCHET INSTEAD OF A CLEAN FAIL
#   These nine sites are real, known, and owned by the docs-correction pass. Line numbers churn
#   under every unrelated doc edit, so pinning them by line would break daily. Counts do not churn.
#   verify-maf-doc-api-contracts.sh fails if a file exceeds its number or if an unlisted file has
#   any, so a NEW defect cannot hide behind this list. When a fix lands, the count only becomes
#   slack — the script prints a notice telling you to lower it. Numbers here may only go DOWN.
#
#   The compiled harness in tests/docs/DocSnippets/ already carries the corrected form of every one
#   of these sites, so the real check is green; this list only keeps the fast pre-filter quiet.
